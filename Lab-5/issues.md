# Lab 5: Static Code Analysis — Issue Documentation

This document records the security, correctness, code quality, and style issues identified in the original `pet_shelter.py` script. Findings are classified by detection mechanism (Bandit, Pylint, Flake8, and Manual Review) with original line numbers, severity, plain-language problem descriptions, and implemented remediation approaches.

## Issues Table

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| **SQL Injection via String Formatting** (`B608`, `C0209`) | Security / CWE-89 (Medium severity, Bandit) | 10 | The `INSERT` SQL statement uses Python `%` string formatting (`VALUES ('%s', '%s', %d, 0)`). Untrusted input in `name` or `species` containing quotes or SQL syntax can break query structure and execute arbitrary SQL commands. | Refactored the query to use parameterized placeholders (`VALUES (?, ?, ?, 0)`) with a parameter tuple `(name, species, age)`, delegating safe escaping and type binding to the SQLite driver. |
| **Insecure Pseudo-Random Number Generator** (`B311`) | Security / CWE-330 (Low severity, Bandit) | 22 | Adoption confirmation codes are generated using `random.randint()`. Python's standard `random` module uses the Mersenne Twister algorithm, which is completely deterministic and predictable, making it unsuitable for security-sensitive tokens or identifiers. | Replaced `random.randint()` with `secrets.SystemRandom().randint(1000, 9999)` from Python's standard `secrets` library, which relies on cryptographically secure OS-level randomness. |
| **Silent Exception Suppression via Try-Except-Pass** (`B110`, `W0718`) | Security / Robustness (Low severity, Bandit; Warning, Pylint) | 36–37 | `clearUnadopted()` wraps query execution in a broad `try: ... except Exception: pass` block. This silently discards database locks, connection failures, schema errors, or operating system errors without logging or feedback. | Replaced `except Exception: pass` with targeted `sqlite3.Error` exception handling, logged the error using `logger.error()`, and returned the integer count of affected rows (`0` on failure). |
| **Mutable Default Argument** (`W0102`) | Bug / Logic (Warning, Pylint) | 9 | `registerPet` defines `tags=[]` as a default parameter. In Python, default arguments are created once when the function is defined. Multiple invocations omitting `tags` append species names to the same persistent list across calls, corrupting pet metadata. | Changed the parameter default to `tags=None` and initialized a fresh list inside the function body (`if tags is None: tags = []`), isolating state between function calls. |
| **Bare Exception Handler Masking Logic Crash** (`W0702`, `E722`) | Bug / Robustness (Warning, Pylint; Error, Flake8; Manual Review) | 28–30 | `oldestAvailable()` fetches a row and subscripts `row[0]`. When no pets are available, `fetchone()` returns `None`, causing a `TypeError`. The code relied on an empty bare `except:` to mask this crash, which also concealed any database execution errors. | Added an explicit guard `if row is not None: return row[0]`, returned `None` when empty, and restricted exception catching strictly to `sqlite3.Error` with logging. |
| **Unchecked Adoption of Nonexistent Pet ID** | Logic Bug / Data Integrity (Manual Review) | 15–18 | `adopt(pet_id)` unconditionally incremented `adoption_count += 1` even if the pet ID did not exist or the animal was already adopted (`rowcount == 0`), corrupting shelter statistics. | Updated query to `WHERE id = ? AND adopted = 0`, evaluated `cur.rowcount > 0` before recording adoption, and returned a boolean indicating adoption status. |
| **Global State Mutation** (`W0603`, `C0103`) | Code Quality / Maintainability (Warning, Pylint) | 6, 16 | The script used `global adoption_count` inside `adopt()`, tightly coupling function execution to module-level state and hindering modularity, unit testing, and reusability. | Replaced the global counter variable with an encapsulated state dictionary (`adoption_stats = {"count": 0}`) and verified compatibility with shelter status calculations. |
| **Non-Standard CamelCase Function Naming** (`C0103`) | Style / Convention (Convention, Pylint) | 9, 21, 25, 33, 40 | Function names (`registerPet`, `adoptionCode`, `oldestAvailable`, `clearUnadopted`, `shelterStatus`) violated PEP 8 function naming conventions. | Renamed functions to standard snake_case (`register_pet`, `adoption_code`, `oldest_available`, `clear_unadopted`, `shelter_status`). |
| **Line Length Exceeded 79/100 Characters** (`E501`, `C0301`) | Style / Formatting (Error, Flake8; Convention, Pylint) | 5, 10, 27 | SQL DDL and DML statements exceeded the 79-character limit (reaching 116 characters), impairing readability in standard terminal diffs and code review tools. | Reformatted multi-line SQL statements using multi-line strings and wrapped function arguments cleanly within 79 characters per line. |
| **Multiple Statements on Single Line** (`E701`, `C0321`) | Style / Formatting (Error, Flake8; Convention, Pylint) | 41 | `if adoption_count > 0: return "active"` compressed a conditional and return statement into a single line, violating PEP 8 compound statement rules. | Split the condition and return statement onto separate indented lines. |
| **Missing Module and Function Docstrings** (`C0114`, `C0116`) | Documentation / Quality (Convention, Pylint) | 1, 9, 15, 21, 25, 33, 40, 45 | The original module and its functions lacked docstrings explaining their purpose, parameters, return values, and behavior. | Added complete PEP 257 docstrings for the module and each individual function. |
